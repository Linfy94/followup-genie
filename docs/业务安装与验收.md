# 业务安装与验收

## 先定验收标准

业务试用通过必须同时满足：

1. 能读到指定腾讯文档台账，但台账修改时间和内容前后完全不变。
2. 每个项目都能归入明确去向：要催、未超期、终止、暂缓或范围外。
3. 随机抽查至少 3 个项目，节点、停滞天数和是否催办均与台账一致。
4. 演练不发消息、不写状态；正式测试只发送到测试群。
5. 凭证、客户清单、真实配置和运行状态不进入 Git。

任一项不满足，就停止扩大试用并记录问题。

## 业务负责人需要准备

- 一张用于测试的腾讯文档项目台账，优先使用副本。
- 业务线名称、稳定唯一的项目编号列、项目名称列。
- 每个流程节点的进入条件、超期天数、重复提醒间隔。
- 明确的终止、暂缓和范围外判断。
- 腾讯文档开放平台凭证。
- 仅用于测试的企业微信群机器人 Webhook。

不要在聊天中发送完整凭证。由业务本人把凭证填入本地 `.env`。

## 四阶段上线

### 第一阶段：只检查配置

运行“只查配置，不联网”。修正所有红色错误，黄色提示逐条确认。

### 第二阶段：只读演练

运行“试跑，不发消息、不写状态”。保存输出，检查台账修改时间没有变化。

### 第三阶段：测试群投递

只连接测试群，手动触发一次。核对群内清单与本地输出一致，失败时不能把项目记为已通知。

### 第四阶段：低频自动化

连续 3 个工作日人工核对后，再创建每日自动化。首周保留人工清单作为对照。
