# 企业微信文档接入（从零安装）

企业微信文档读取使用 `wecom-cli` 的**智能机器人**身份；催办消息推送使用的是企业微信群的
**群机器人 Webhook**。这是两条独立通道：Webhook 地址不能读文档，智能机器人凭证也不能
代替群 Webhook 发消息。

## 四道门

1. **命令行工具**：本机有 Node.js 18+ 和 `wecom-cli`。
2. **智能机器人初始化**：业务本人在本机执行初始化并扫码授权。
3. **文档能力**：机器人已开通「获取成员文档内容」能力。
4. **文档对象权限**：机器人本身能读取目标在线表格。

不要把“业务人员能打开文档”当成第 4 项已经通过。10 人以上企业中，机器人是独立身份，
默认不会继承业务人员的既有文档权限。

## 第 1 步：安装与初始化

安装助手先说明会安装一个全局命令行工具，得到同意后执行：

```bash
npm install -g @wecom/cli
wecom-cli init
```

`init` 会引导扫码；扫描和授权应由准备让机器人读取文档的业务主体完成。不要把 Bot ID、
Secret、二维码内容或本机凭证粘贴进聊天、Git 或配置 JSON。

安装完成后，先确认命令存在：

```bash
wecom-cli --help
```

## 第 2 步：开通机器人文档能力

由该智能机器人的管理员在企业微信「工作台 → 智能机器人」中开通
「获取成员文档内容」能力。它解决的是机器人是否有**文档能力**，不是某一份文档是否
已经允许该机器人读取。

## 第 3 步：取得文档定位字段

配置使用：

| 配置项 | 填什么 |
|---|---|
| `url` | 企业微信在线表格的完整访问链接（`doc.weixin.qq.com/sheet/…` 或支持的智能表格链接） |
| `sheet_id` | 该文档内部的子表 ID |

`sheet_id` 只在同一文档内唯一，必须与 `url` 成对填写。不要把群 Webhook、机器人凭证或
腾讯文档链接填进这里。

## 第 4 步：只读探针

先在程序目录执行：

```bash
wecom-cli doc sheet_get_info --json '{"url":"<完整企微文档链接>"}'
```

只在返回 `errcode: 0` 后，才把返回的 `sheet_id` 写入 `ledgers.json`，再运行
`doctor.py`。程序只调用 `sheet_get_info` 与 `get_doc_content` 两个读取命令；不会写入、
改格式或增删行列。

## 错误只按当前这一项处理

| 错误码 / 现象 | 依据 | 原因 | 唯一处理动作 |
|---|---|---|---|
| 找不到 `wecom-cli` | 实测 | 尚未安装，或定时任务找不到安装目录 | 先完成第 1 步；终端有但定时任务没有时，修定时任务 PATH，不要重复初始化 |
| `851008` | **实测** 2026-08-05 | 智能机器人缺「获取成员文档内容」能力 | 由机器人管理员完成第 2 步；不要改用群 Webhook |
| `851014` | **实测** 2026-08-14 | 智能机器人的「文档」使用权限**到期**（不是凭证坏了，也不是扫码过期）| 由**机器人创建者**在企业微信「工作台 → 智能机器人」找到该机器人续授权。🔴 **重新扫码没有用**，`wecom-cli init` 解决不了这一条。实测有效期约 9 天（凭证写于 08-05 15:06，08-14 09:00 还能读，10:28 起全部报错），**会复发** |
| `640002` | **实测** 2026-08-10 | 文档 ID / 文件 ID 不存在 —— 链接写错或文档已删 | 核对 `url` 是否与浏览器里能打开的那份一致；这一条与权限无关，改权限没有用 |
| `851003` | ⚠️ **未实测**（依据接口文档推断）| 机器人对目标文档没有对象权限 | 请文档所有者或企业微信管理员确认能否把该文档显式授权给该智能机器人；重新扫码、换分享链接或给业务人员加协作者都不能替代它。**注意这与 `851008` 是两层**：能力授权（`851008`）一次开通即对全部文档生效，而这一条是单份文档的对象权限 |
| `851002`（`sheet_get_info`） | ⚠️ 部分实测 | 链接不是兼容的企业微信在线表格，或文档类型不匹配 | 核对链接平台、完整 URL 与 `source=wecom_doc`；此时还没有可用的子表结构，不要修改权限 |
| `851002`（`get_doc_content`） | ⚠️ **未实测** | 结构可读，但正文读取接口不兼容该文档类型 | 停止接入并保留错误；当前适配器无法读取，不要修改 `sheet_id` 或反复授权 |
| 子表不存在 | 实测 | `url` 与 `sheet_id` 不属于同一份文档，或子表已调整 | 用第 4 步重新列出子表后更新配置 |

🔴 **「依据」这一列不是形式主义。** 本项目对这两份台账只观测到过
`0`（成功）、`851008`（能力未授权）、`640002`（链接写错）三种返回；
`851002` 只在**白名单之外**的 `smartsheet_*` 命令上见过（返回
`incompatible doc type`），从 `sheet_get_info` / `get_doc_content` 上没见过；
`851003` **一次都没出现过** —— 2026-08-05 探路时预期是它，实际返回的是 `851008`。

标「未实测」的行照样给出建议，因为出事时有个方向总比没有强；但**照着做没解决时，
不要反复加码同一个动作**，把原始 `errcode` 和 `errmsg` 留下来重新判断。

企业微信文档目前不能提供“读取前后最后修改时间”的等价指纹；因此只读性依赖代码中固定的
读取命令白名单。自检会明确提示这项边界，不能把“未做指纹核对”误说成“已经核对未修改”。

🔴 **机器人的文档权限会到期，实测约 9 天一轮**（2026-08-14 首次撞上，见上表 `851014`）。
到期表现为退出码 1 + 明确报故障，**不会伪装成「今天没有要催的」**。
续期只能由机器人创建者在企业微信里做，程序侧无法自动续。
