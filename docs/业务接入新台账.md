# 业务接入新台账

## 业务先回答这 10 个问题

1. 这张台账解决的是哪条业务线？
2. 哪一列是永远不重复、尽量不变化的项目编号？
3. 哪一列是项目名称？
4. 哪些项目属于本次催办范围？
5. 每个流程节点分别由哪些字段和值判断？
6. 每个节点停留多少天开始提醒？
7. 超期后每隔多少天重复提醒？
8. 哪个日期作为首次计算停滞天数的依据？
9. 台账用什么字段明确表示终止或暂缓？
10. 催办清单发到哪里，谁负责核对？

答案不完整时不要让 Agent 猜。先让业务负责人补齐。

## 给 Agent 的接入指令

> 请调用项目跟进精灵，按 `docs/接一条新业务线.md` 为一张新的腾讯文档项目台账生成配置。
> 先向我逐项收集业务线名称、稳定主键、项目名称列、范围、节点、阈值、重复提醒、起算日期、
> 终止与暂缓信号、测试群。不要修改代码，不要覆盖已有配置，不要读取其他无关文档。
> 配置完成后只运行配置检查和只读演练，并输出字段映射表与项目去向对账表。

## 接入完成的判断

- 配置检查无红色错误。
- 所有有效项目都能解释去向。
- 3 个普通项目、1 个终止项目、1 个暂缓项目人工核对一致。
- 台账版本和修改时间没有变化。
- 业务负责人能独立解释每条规则为什么这样配置。

更详细的字段、规则和测试方法见 [接一条新业务线](接一条新业务线.md)。
